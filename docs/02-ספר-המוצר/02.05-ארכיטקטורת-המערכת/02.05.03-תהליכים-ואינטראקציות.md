# 02.05.03 — תהליכים ואינטראקציות

שרשרת המודיעין העקרונית של Stock Sentinel היא:

Collect
→ Normalize
→ Correlate
→ Interpret
→ Explain
→ Evaluate Portfolio Impact
→ Present
→ Deliver.

## Source-Grounded Understanding

כאשר קיים מקור סמכותי:

1. המקור המלא נקרא ככל שהפורמט מאפשר.
2. מזוהים Facts / Developments מועמדים.
3. טענות עובדתיות נקשרות לראיות במקור.
4. הממצאים מדורגים לפי מהותיות למשקיע.
5. נוצרת תמצית עובדתית קצרה.
6. רק לאחר מכן מתווספים Interpretation ו־Portfolio Impact.

המטרה היא למנוע מצב שבו ניסוח משכנע קודם לביסוס העובדות.

## Correlation

אירועים ממקורות שונים יכולים להתאחד ל־Intelligence Story כאשר הם מתארים אותה התפתחות.

מקורות משניים יכולים להעשיר את ההקשר, אך חזרה מרובה על אותה טענה אינה הופכת אותה לעובדה.

## Opening / Initialization

לאחר קבלת Portfolio Truth סמכותי ולפני צריכת התיק ב־runtime, כל holding
שהוצג לראשונה עובר Opening עצמאי:

Accepted Portfolio Truth
→ authoritative introduction
→ Sentinel-owned verified identity
→ bounded research
→ Sentinel verification and explicit dispositions
→ `LEARNING` / `READY`
→ runtime eligibility.

Portfolio Truth נשאר מקור הסמכות היחיד לחברות בתיק. Opening אינו משנה אותו
ואינו יוצר סמכות תיק שנייה. זכאות ל־runtime דורשת גם חברות נוכחית ב־Portfolio
Truth וגם מצב Opening `READY` השייך למחזור החברות הרציף הנוכחי. holding נוכחי
ללא מצב Admission כזה נשאר חלק מן התיק הסמכותי אך אינו נמסר ל־runtime.

הכלל חל גם על holdings שהיו קיימים לפני חיבור חוזה Opening הנוכחי: הם עוברים
Legacy / Current-Holding Adoption באמצעות אותו lifecycle קיים, בלי ליצור
Portfolio authority, lifecycle או persistence מקבילים. הסרה מלאה ולאחריה
הצגה מחדש מתחילה מחזור חברות חדש; מצב `READY` ממחזור קודם אינו מקנה זכאות
למחזור החדש.

זהות Opening היא Sentinel-owned וכוללת `ticker`, ‏`company_name`, ‏`CIK`
ו־`exchange` מאותה רשומת SEC סמכותית. תוצאת המחקר מכילה `0..10`
`OpeningFactCandidate` בלבד; כל מועמד כולל `fact`, ‏`category` ו־`evidence`.
ה־provider אינו מוסמך לקבוע או להעשיר זהות, disposition, materiality או
readiness.

לכל מועמד נשמרת בדיוק החלטת Sentinel אחת: `VERIFIED`, ‏`REJECTED` או
`UNRESOLVED`. במסלול אימות SEC המקומי הנוכחי, הוכחה עצמאית מול מסמך SEC
סמכותי מייצרת `VERIFIED`; תוצאה שלא ניתן להוכיח בבטחה מייצרת `UNRESOLVED`.
זיהוי סתירה חיובית לצורך `REJECTED` אינו חלק מהמסלול הנוכחי.

`READY` דורש זהות מלאה ומאומתת, מחקר bounded שהושלם בהצלחה, לפחות עובדה
אחת במצב `VERIFIED`, והחלטה מפורשת לכל מועמד. `time_zero` יציב לאורך אותו
מחזור חיים; הסרה והצגה מחדש יוצרות מחזור חדש, בעוד שינוי רציף בכמות או
בעלות הממוצעת אינו יוצר Opening חדש. מצב `LEARNING` נשמר וניתן לשחזור עם
`time_zero` המקורי.

החיבור ל־runtime משתמש בגבול הדינמי הקיים של
`SourceRuntimeFactory.portfolio_provider`; לא נוסף filter, registry או מקור
Portfolio מקביל. באינטגרציית Opening admission המוקדמת בלבד, רכיבי
ה־runtime downstream לא שונו; אין בכך טענה שנותרו ללא שינוי בכלל
הדלתא המצטברת של R&D 002.


### Target-scoped Reference Source identity

Scope follows the task, not the source. A source is a reference source; the
target entity is the unit of work. Source caching/indexing may optimize access,
but must not expand target validation to unrelated entities.

For SEC Opening identity, locate the requested company's authoritative
association(s) in `company_tickers_exchange.json`, then strictly validate the
target's `ticker`, `company_name`, `CIK` and `exchange` from its own association.
Unrelated companies need not form valid `CompanyIdentity` objects before the
target can resolve. Preserve source/envelope integrity necessary for reliable
lookup, strict target validation, target ambiguity detection and fail-closed
behavior when the target cannot be reliably identified. Perplexity remains
research-only and cannot create or enrich identity.

## Source Observation / Monitoring Boundary

Opening קובע Admission readiness ומחזיק `time_zero` יציב למחזור החברות.
Source Observation אחראי ל־source-object baseline, ל־NEW/CHANGE detection
ול־pending observation/replay/ACK. NotificationHistory נשאר delivery dedup
בלבד ואינו מקור סמכות ל־source newness או למחזור החיים של holding.

הכלל המחייב הוא `learn past, monitor forward`: occurrence שמועדו הסמכותי
קודם ל־`time_zero` יכול להילמד כהקשר אך אינו נעשה `NEW` רק משום שהתגלה
מאוחר יותר. occurrence ב־`time_zero` או אחריו יכול להיכנס למסלול
NEW/CHANGE. discovery/processing time אינו תחליף למועד occurrence סמכותי;
מועד חסר או לא תקין נכשל fail-closed ל־NEW-alert admission.

למידת היסטוריה לאחר `READY` אינה Gate נוסף ויכולה להתקיים במקביל לניטור.
SEC, FDA ו־ClinicalTrials.gov מיישמים את הגבול הזה ב־Alpha הנוכחי.
ClinicalTrials מפריד bootstrap היסטורי מ־steady-state observation bounded.
Source Observation נשמר durable; acquisition חלקי, capped או כושל אינו
רשאי להציג baseline חלקי כאמת מלאה.

## Presentation Flow

התוצר המוצג מפריד ככל שנדרש בין:
- מה קרה;
- הראיות והמקור;
- משמעות האירוע;
- ההשפעה האפשרית;
- הקשר לתיק;
- מה ראוי לבדיקה.

הצגה אינה אמורה להסתיר אי־ודאות שקיימת בשכבות הקודמות.
