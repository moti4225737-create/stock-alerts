# 02.05.03 — תהליכים ואינטראקציות

שרשרת המודיעין העקרונית של Stock Sentinel היא:

Collect
→ Normalize
→ Correlate
→ Interpret
→ Explain
→ Evaluate Portfolio Impact
→ Present
→ Deliver.

## Source-Grounded Understanding

כאשר קיים מקור סמכותי:

1. המקור המלא נקרא ככל שהפורמט מאפשר.
2. מזוהים Facts / Developments מועמדים.
3. טענות עובדתיות נקשרות לראיות במקור.
4. הממצאים מדורגים לפי מהותיות למשקיע.
5. נוצרת תמצית עובדתית קצרה.
6. רק לאחר מכן מתווספים Interpretation ו־Portfolio Impact.

המטרה היא למנוע מצב שבו ניסוח משכנע קודם לביסוס העובדות.

## Correlation

אירועים ממקורות שונים יכולים להתאחד ל־Intelligence Story כאשר הם מתארים אותה התפתחות.

מקורות משניים יכולים להעשיר את ההקשר, אך חזרה מרובה על אותה טענה אינה הופכת אותה לעובדה.

## Opening / Initialization

לאחר קבלת Portfolio Truth סמכותי ולפני צריכת התיק ב־runtime, כל holding
שהוצג לראשונה עובר Opening עצמאי:

Accepted Portfolio Truth
→ authoritative introduction
→ Sentinel-owned verified identity
→ bounded research
→ Sentinel verification and explicit dispositions
→ `LEARNING` / `READY`
→ runtime eligibility.

Portfolio Truth נשאר מקור הסמכות היחיד לחברות בתיק. Opening אינו משנה אותו
ואינו יוצר סמכות תיק שנייה. holding חדש שאינו `READY` נשאר בתיק הסמכותי אך
אינו נכלל בתצוגת התיק שמספק ה־`portfolio_provider` הקיים ל־runtime. holdings
שהיו נוכחים ברציפות נשארים זכאים ואינם נדרשים ל־Opening חדש.

זהות Opening היא Sentinel-owned וכוללת `ticker`, ‏`company_name`, ‏`CIK`
ו־`exchange` מאותה רשומת SEC סמכותית. תוצאת המחקר מכילה `0..10`
`OpeningFactCandidate` בלבד; כל מועמד כולל `fact`, ‏`category` ו־`evidence`.
ה־provider אינו מוסמך לקבוע או להעשיר זהות, disposition, materiality או
readiness.

לכל מועמד נשמרת בדיוק החלטת Sentinel אחת: `VERIFIED`, ‏`REJECTED` או
`UNRESOLVED`. במסלול אימות SEC המקומי הנוכחי, הוכחה עצמאית מול מסמך SEC
סמכותי מייצרת `VERIFIED`; תוצאה שלא ניתן להוכיח בבטחה מייצרת `UNRESOLVED`.
זיהוי סתירה חיובית לצורך `REJECTED` אינו חלק מהמסלול הנוכחי.

`READY` דורש זהות מלאה ומאומתת, מחקר bounded שהושלם בהצלחה, לפחות עובדה
אחת במצב `VERIFIED`, והחלטה מפורשת לכל מועמד. `time_zero` יציב לאורך אותו
מחזור חיים; הסרה והצגה מחדש יוצרות מחזור חדש, בעוד שינוי רציף בכמות או
בעלות הממוצעת אינו יוצר Opening חדש. מצב `LEARNING` נשמר וניתן לשחזור עם
`time_zero` המקורי.

החיבור ל־runtime משתמש בגבול הדינמי הקיים של
`SourceRuntimeFactory.portfolio_provider`; לא נוסף filter, registry או מקור
Portfolio מקביל, ורכיבי ה־runtime downstream לא שונו.

## Presentation Flow

התוצר המוצג מפריד ככל שנדרש בין:
- מה קרה;
- הראיות והמקור;
- משמעות האירוע;
- ההשפעה האפשרית;
- הקשר לתיק;
- מה ראוי לבדיקה.

הצגה אינה אמורה להסתיר אי־ודאות שקיימת בשכבות הקודמות.
