# ניהול ספרינטים

ספרינט הוא יחידת עבודה ממוקדת בעלת מטרה ברורה, Scope מוגדר ו־Exit State שניתן לאמת.

## סמכות סגירה

ספרינט או שלב רשמי כפופים ל־:

`פרוטוקול-השינוי-האימות-המסירה-והסגירה-הסמכותי.md`

Definition of Done של ספרינט הוא דרישה פנימית בפרוטוקול הסמכותי ואינו Closure Authority נפרד.

## משמעת Scope

אין לפתוח מסלול עבודה חדש במהלך ספרינט אלא אם מתגלה:

- Crash;
- טעות מהותית;
- סיכון Production מהותי;
- בעיה ארכיטקטונית המחייבת טיפול;
- או חסם שמונע את השגת מטרת הספרינט.

ממצא חשוב שאינו מחייב עצירה נרשם להמשך ואינו משתלט על הספרינט הפעיל.

## Definition of Done

בתוך הפרוטוקול הסמכותי נדרש לפחות:

- הערך שנקבע לספרינט סופק;
- ה־Scope נשמר;
- הבדיקות הממוקדות עברו;
- Full Regression עבר;
- השינוי נבדק;
- Commit ו־Push עברו את הבקרות והאישורים הרלוונטיים;
- Branch / CI / Deployment / Runtime validations עברו כאשר הם רלוונטיים;
- המאגר נשאר במצב ידוע ונקי;
- בוצע Documentation Checkpoint.

גם עמידה ברשימה זו אינה עוקפת דרישה רלוונטית אחרת בפרוטוקול הסמכותי.

## Documentation Checkpoint

סיום ספרינט משמעותי כולל כחלק מהפרוטוקול:

1. Current Truth — עדכון המצב התקף בארכיון.
2. Chronicle — תיעוד מתי, למה וכיצד השתנה המוצר.
3. Traceability — חיבור למסמכים, בדיקות, החלטות, Commit / Tag / Version והראיות הרלוונטיות.

## R&D Unit and Conversation Continuity Protocol

### נוהל רציפות יחידות R&D ושיחות עבודה

נוהל זה הוא פרוטוקול תפעולי כפוף לניהול יחידות R&D ולרציפות בין שיחות
עבודה. הוא אינו Closure Gate, אינו סמכות חלופית ואינו מחליף את
`פרוטוקול-השינוי-האימות-המסירה-והסגירה-הסמכותי.md`.

הנוהל מספק הקשר וראיות לפרוטוקול הסגירה הסמכותי היחיד. רק הפרוטוקול
הסמכותי רשאי לקבוע Closure של ספרינט או שלב רשמי. סיום שיחה והשלמת Handoff
אינם כשלעצמם Closure.

### זיהוי ומספור

- המזהה הקנוני הוא `R&D NNN`.
- המספור הוא תלת־ספרתי, רציף וכלל־מאגרי.
- מזהה שהוקצה הוא immutable ואינו ניתן לשימוש חוזר.
- כותרת יחידה נכתבת בתבנית `R&D NNN — Title`.
- שם קובץ Chronicle עתידי נכתב בתבנית
  `YYYY-MM-DD-rnd-NNN-<short-slug>.md`.
- לכל יחידה נרשמים predecessor ו־successor כאשר הם קיימים.
- `NEXT` מציין יחידה רשומה שטרם נפתחה; אין להציג אותה כ־`OPEN` לפני פתיחה
  מפורשת.

### Opening Block מחייב

כל שיחה הפותחת יחידת R&D מתחילה בבלוק הבא, המועתק מן המידע הסמכותי
העדכני ולא מזיכרון השיחה הקודמת:

```text

Title:
Status:
Predecessor:
Authoritative handoff:

Current objective:

Explicitly deferred / out of scope:

External-state verification required:

- branch
- HEAD
- upstream
- working-tree state
- protected local files

Validation / evidence baseline:

Required cadence / governing protocol references:

Required end-of-conversation handoff:
- achieved state
- evidence
- unresolved / deferred work
- repository state
- Production / external state
- successor R&D unit
```

### Working Cadence

ה־Opening Block אינו משכפל הוראות עבודה. יחידת R&D מפנה לפרוטוקול השינוי,
האימות, המסירה והסגירה הסמכותי, למסמכי ה־TDD, ל־Documentation Checkpoint
ולבתי הסמכות התחומיים החלים עליה. ה־Scope, פעולות אסורות, אישורי Product
Owner וגבולות Production / external systems נשמרים לאורך השיחה.

### End-of-Conversation Handoff

לפני סיום שיחה נרשמים ב־Chronicle או בבית הסמכותי המתאים:

- המצב שהושג והראיות התומכות בו;
- מה לא הושלם, מה לא הוכח ומה נדחה במפורש;
- מצב branch, ‏HEAD, upstream, working tree ופעולות Git שטרם בוצעו;
- מצב Production ושירותים חיצוניים, כולל `NOT VERIFIED` כאשר אין ראיה חיה;
- החלטות וחוזים שנותרים סמכותיים;
- מזהה היחידה הבאה ומעמדה;
- הפעולה הראשונה המומלצת ביחידה הבאה.

Handoff סוגר את רציפות השיחה בלבד. סטטוס היחידה ב־R&D Register וסטטוס
Closure לפי הפרוטוקול הסמכותי נרשמים בנפרד ואסור להסיק אחד מן האחר.
