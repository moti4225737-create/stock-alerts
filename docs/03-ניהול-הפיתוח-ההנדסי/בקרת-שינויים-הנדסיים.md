# בקרת שינויים הנדסיים

מנגנון הבקרה מוודא ששינוי במימוש נכנס למוצר בצורה מבוקרת, ממוקדת וניתנת לעקיבה.

## לפני Commit

- Git status נבדק.
- הקוד הרלוונטי נבדק.
- אין שינויים שאינם קשורים למשימה.
- השינוי Cohesive.
- שטח השינוי קטן ככל שנדרש להשגת המטרה.
- Backward Compatibility נשמרת כאשר היא נכונה ואינה חוסמת התפתחות נדרשת.
- אין Temporary Production Code.
- הפתרון ברור ולא Clever ללא צורך.
- הבדיקות הממוקדות וה־Regression עברו.

## לפני Push

- Commit אושר.
- Branch אושר.
- Destination אושר.

## סמכות

פעולות משמעותיות אינן מקבלות אישור אוטומטי מעבודה קודמת.

Commit, Push, Release, מחיקה רחבה, Refactor רחב, שינוי Secrets ופעולות דומות מחייבים את שערי האישור הרלוונטיים.
