# ניהול גישה, הרשאות וחשיפת מידע

ענף זה מגדיר מי רשאי לגשת לנכסי Stock Sentinel, לאיזה מידע, לאיזו מטרה, באיזה שלב ולכמה זמן.

המטרה היא לאפשר עבודה, ביקורת, השקעה, שותפות או עסקה בלי לחשוף קוד, ארכיטקטורה, IP, Secrets או מידע רגיש מעבר לנדרש.

## עקרונות יסוד

- Default Deny — בהיעדר הרשאה מפורשת, אין גישה.
- Least Privilege — ניתנת רק ההרשאה המינימלית הדרושה.
- Need-to-Know — גישה נקבעת לפי צורך ממשי.
- Purpose Bound — הרשאה ניתנת למטרה מוגדרת.
- Time Bound — הרשאות שאינן קבועות מקבלות תוקף מוגדר.
- Separation of Duties — ביצוע פעולה אינו מעניק אוטומטית סמכות לאשרה.
- No Self-Escalation — גורם אינו רשאי להרחיב לעצמו הרשאה.
- Traceability — הקצאה, שינוי ושלילה של הרשאה משמעותית ניתנים לעקיבה.
- Disclosure by Stage — חשיפה חיצונית גדלה רק לפי התקדמות התהליך והצורך.
- Secrets חיים אינם תוכן ארכיוני ואינם מוצגים בערכם המפורש.

## סמכות

בעל המוצר הוא סמכות האישור העליונה והיחידה להקצאה, הרחבה, שינוי או שלילת הרשאה, אלא אם האציל בעתיד סמכות מוגדרת ומצומצמת במפורש.

ביצוע טכני של הרשאה מאושרת יכול להיות מואצל ל־Access Administrator בלי להעביר אליו את סמכות ההחלטה.

## הגנת IP

מספיק מידע כדי להשיג את המטרה המאושרת — לעולם לא יותר מידע מכפי שנדרש.

כאשר ניתן להשיג את מטרת הבדיקה באמצעות ראיות, תוצאות, Interfaces, תרשימים, Redaction, Demo או סביבת ביקורת מוגנת — אלה עדיפים על חשיפה עמוקה של קוד או לוגיקה קניינית.
