# מבנה הארכיון וכללי התיעוד

ארכיון Stock Sentinel הוא Controlled Source of Truth המתוחזק במקביל לקוד ולבדיקות.

## עקרונות מבנה

- עברית היא שפת הניווט והארגון הראשית.
- אנגלית נשמרת למונחים מקצועיים, שמות רכיבים, תקנים ומקומות שבהם היא משפרת דיוק.
- אין צורך לשכפל כל כותרת בשתי שפות.
- כלל שמכיל ילדים מיוצג כתיקייה עם README.
- פרט סופי מיוצג כמסמך Markdown.
- עומק חדש נוצר רק כאשר מספר פרטים יוצרים משפחה טבעית: פרט + פרט + ... = כלל.
- לכל מידע סמכותי יש Natural Home אחד.
- אין ליצור כמה מסמכים סמכותיים לאותו נושא.

## מבחן מיקום

כאשר מיקום אינו ברור:

1. מבררים את המטרה והמהות של הפריט.
2. בודקים אם מהותו Product, Architecture או Engineering.
3. מפעילים את מבחן פרט + פרט = כלל.
4. מזהים את הבית הטבעי.
5. מציגים הצעת מיקום לאישור בעל המוצר.
6. רק לאחר אישור יוצרים או מעבירים את המסמך הסמכותי.

כאשר השאלה היא האם פריט שייך ל־Engineering, מבחן עזר הוא:
אם הוא קיים בעיקר כדי להגן על או לנהל Build, Change, Test או Release — מהותו הנדסית.

## שינוי מבנה

שינוי במבנה, שמות, מיקום סמכותי או סדר הארכיון אינו שינוי קוסמטי בלבד.

שינוי כזה דורש:
- בדיקת השפעה;
- בדיקת כפילויות;
- שמירת Traceability;
- אישור מפורש של בעל המוצר.

## Legacy

מסמך Legacy אינו נמחק או מועבר לפני שהוכח שכל תוכן תקף בו קיבל בית סמכותי מתאים או שסומן במפורש כלא תקף.
