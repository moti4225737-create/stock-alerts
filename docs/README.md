# ארכיון המוצר — Stock Sentinel

ארכיון המוצר הוא הייצוג הרשמי, המבוקר, ההיסטורי והניתן לעקיבה של Stock Sentinel.

הארכיון הוא חלק מהמוצר ופועל במקביל ל־R&D:
הפיתוח והייצור יוצרים ומשנים את מצב המוצר; הארכיון מתעד, משמר, מסביר ומאפשר לעקוב אחר המצב המאומת והחלטותיו.

הארכיון אינו מחליף את הקוד, הבדיקות או סביבת הייצור, ואינו מכתיב שינוי למוצר רק כדי להתאים למסמך.

## מבנה הארכיון

### 01 — יסודות המוצר
הזהות, התכלית והעקרונות היציבים שעליהם Stock Sentinel עומד.

### 02 — ספר המוצר
מתאר מהו Stock Sentinel, מה עליו לעשות, כיצד הוא בנוי ולאן הוא מתפתח.

### 03 — ניהול הפיתוח ההנדסי
הדרך המבוקרת שבה בונים, משנים, מאמתים, מוסרים וסוגרים שינוי תוך שמירת יציבות, עקיבות ומשמעת הנדסית.

הבית הסמכותי היחיד לפרוטוקול End-to-End נמצא כאן:

`03-ניהול-הפיתוח-ההנדסי/פרוטוקול-השינוי-האימות-המסירה-והסגירה-הסמכותי.md`

### 04 — תפעול המערכת
מתאר כיצד מפעילים את Stock Sentinel החי, מנטרים את בריאותו ומתמודדים עם כשלים והתאוששות.

### 05 — אבטחת איכות, אימות ותיקוף
מתאר כיצד מוכיחים שהמערכת והשינויים בה נכונים, עומדים בחוזים ומשיגים את מטרתם.

### 06 — ניהול הידע ורציפות התיעוד
מגדיר כיצד נשמר ה־Source of Truth, כיצד מתועד שינוי לאורך זמן וכיצד נשמרת רציפות הידע.

## עקרונות ניווט

- עברית היא שפת הניווט הראשית.
- מונחים מקצועיים באנגלית נשמרים כאשר הם מוסיפים דיוק.
- כלל שמכיל ילדים מיוצג כתיקייה עם README המשמש שער לענף.
- פרט סופי מיוצג כמסמך Markdown.
- עומק נוסף נוצר רק כאשר פרט + פרט + ... יוצרים כלל טבעי.
- שינוי מבני בארכיון דורש מיפוי ואישור מפורש של בעל המוצר.
- שיחות עבודה אינן Source of Truth ארוך טווח.

## Source of Truth

המסמכים בארכיון מתעדים את מצב המוצר המאומת.

הקוד, הבדיקות, CI וה־runtime הם האמת התפעולית של המימוש וההפעלה.

החוקה מגדירה את גרעין העקרונות שאינו משתנה עם כלי, טכנולוגיה או workflow.

ה־Chronicle שומר מתי, למה וכיצד המוצר השתנה.

## סמכות סגירה

כל ספרינט או שלב רשמי נסגר רק באמצעות הפרוטוקול הסמכותי היחיד.

Documentation Checkpoint הוא שלב פנימי מחייב בתהליך כאשר הוא רלוונטי:

Current Truth
→ Chronicle
→ Traceability
→ Repository History.

השלמת Documentation Checkpoint לבדה אינה Closure.
