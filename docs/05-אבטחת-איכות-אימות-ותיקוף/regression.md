# Full Regression

Full Regression בודק ששינוי חדש לא פגע בהתנהגויות שכבר הוכחו במערכת.

## עיקרון

בדיקה ממוקדת מוכיחה את השינוי החדש.

Regression מוכיח שהמערכת הקיימת עדיין עומדת בחוזים שלה לאחר השינוי.

שניהם נדרשים כאשר הם רלוונטיים.

## בקרה לפני Commit

לפני Commit של שינוי קוד משמעותי:

1. הבדיקות הממוקדות עוברות.
2. Full Regression עובר.
3. כשל חדש מוסבר ואינו מתקבל אוטומטית כ"שינוי צפוי".
4. אין משנים בדיקה רק כדי להחזיר Green בלי להבין איזה חוזה השתנה.

בקרה זו היא חלק מהפרוטוקול הסמכותי ואינה Closure Authority עצמאית.

## חוזים משתנים

כאשר שינוי מוצרי או ארכיטקטוני מאושר משנה חוזה קיים, הבדיקה עצמה יכולה להשתנות — אך רק כחלק מהחלטת השינוי, לא בדיעבד כדי להתאים את הבדיקה למימוש.
